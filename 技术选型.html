技术选型

首先如果只考虑技术上，我更偏向于这一套：

前端采用 React 技术栈，后端继续完全复用 RuoYi，前端单独做一层 RuoYi 协议适配。

RuoYi 后端本质上提供的是登录、用户、角色、权限、菜单、字典、接口权限、数据权限这些能力。前端只要把它的接口格式、权限字符、动态菜单、字典体系适配好，就可以正常使用 React 技术栈。

选型项 推荐方案 说明
前端框架 React 主前端框架，负责 PC 管理后台和可视化大屏的页面开发
打包工具 Vite 开发体验好，构建速度快，我们之前项目也在用
路由 TanStack Router React 生态里比较成熟的路由方案，需要适配 RuoYi 动态菜单
接口状态 TanStack Query 管理接口数据，比如列表、详情、字典、菜单、统计数据、图表数据
本地状态 Zustand 管理 token、用户信息、roles、permissions、菜单、主题、布局等本地状态
中后台组件库 Ant Design React 生态里成熟的中后台组件库，适合 CRUD 页面和管理后台
普通 CRUD 表单 Ant Design Form 和 Ant Design 组件配合最自然，适合普通新增、编辑、查询表单
复杂业务表单 React Hook Form + Zod 适合复杂表单、动态字段、多步骤表单和 schema 校验
权限控制 自行开发 RuoYi 权限适配层 消费 RuoYi 返回的 roles 和 permissions，封装按钮权限、菜单权限、路由守卫
图表 ECharts 用于统计图表、大屏图表、趋势图、分布图等
地图 OpenLayers 适合自有 GIS、地块边界、离线瓦片、区域图层等场景
小程序 Taro 主栈是 React，Taro 可以尽量保持 React 语法和工程习惯一致
HTTP Client Axios 封装为 RuoYi Client 统一处理 token、请求拦截、响应 code、分页、上传下载、导入导出等；现有 App 和大屏应该已经做了类似封装

Monorepo

repo/
├─ apps/                         # 具体前端应用
│  ├─ admin-web/                 # PC 管理后台
│  ├─ screen-web/                # 可视化大屏
│  └─ mobile-miniapp/            # Taro 小程序
│
├─ packages/                     # 多端复用的公共代码
│  ├─ domain/                    # 业务类型和校验规则
│  ├─ sdk/                       # 接口请求封装，适配 RuoYi 后端
│  ├─ auth/                      # 登录、权限、路由守卫
│  ├─ ui-tokens/                 # 统一颜色、字号、间距、主题变量
│  ├─ ui-react/                  # PC 后台复用组件
│  ├─ ui-mobile/                 # 小程序复用组件
│  └─ charts/                    # ECharts 图表配置、主题和数据转换
│
└─ infra/                        # 工程、部署和脚本
   ├─ ci/                        # CI/CD 配置
   ├─ docker/                    # Docker / Nginx 配置
   └─ scripts/                   # 构建、部署、代码生成脚本

很多能力需要在多个端之间复用，比如类型定义、接口 client、权限判断、字典处理、图表配置、主题变量、测试 mock 等。

所以建议把具体应用放在 apps，把可复用能力放在 packages。
